# 目录整理

本模块以实际磁盘目录为起点，每个直属子目录是独立整理单元。只处理本次选中的磁盘资源；数据库中存在但所选目录下没有的作品，不进入本次整理。

## 使用流程

1. 手填绝对路径，或点击“选择实际文件夹”。点击“预览目录”扫描直属子目录并顺序自动预览前 64 项；根层散落文件另行展示，本次不会处理。
2. 子目录直接展示已整理完成、需要整理、无法自动整理等状态。可停止后续自动预览，也可选择任意子目录单独“重新预览此目录”。媒体完成状态与 DB / 快捷方式完整程度分别检查。超过 64 项时建议缩小范围或分批操作，继续预览会使旧缓存失效，需要重新确认。
3. 右侧使用“目录预览 / 整理目标 / 关联 DB”三个平级页签，首次默认目录预览。目录、目标摘要、状态、阻断问题和预览 / 锁定 / 执行按钮在页签外常驻；设置页直接编辑目标和规则。每个子目录独立保留页签、草稿及浏览位置，切换只改变显示，不重新扫描或提交。结构预览采用索引页式目录浏览器：左侧仅目录树，右侧为当前目录内容，支持整理前 / 后切换。逐文件移动和目标编辑只通过“查看逐文件移动详情”按钮打开独立窗口。整理规则只有“自动”和“通用”两个选项，当前都实例化通用整理类。纯手动类及 VCB / Jsum 旧类与规则 ID 已移除；压制组元数据、单项手填目标和“媒体目录已整理完成”仍保留。
4. 查找并关联已有 DB 记录，或者补齐新记录并明确勾选确认新增。同一实际资源目录可以关联多条作品记录；每条记录可以选择所关联的压制项。
5. 新增和“编辑作品信息”复用收集列表的作品弹窗；提交只更新整理草稿，取消不创建空记录。完整 JSON 与补充收集仍可按需编辑。未知属性和扩展字段保留；日期显示 `YYYY-MM-DD`，保存由共用服务规范化为 `YYYYMMDD`。顶部目标与关联压制路径同步，不自行覆盖未关联压制版本。
   - 已有作品没有压制记录，或者没有当前版本时，可在共享作品弹窗中添加压制版本，并填写格式、组和路径。
   - 可新增补充收集标题及其压制记录，也可移除草稿中的压制行；实际 DB 变更仍须重新预览、锁定和执行。JSON 重排压制项后清除旧位置绑定，必须重新选择对应项。
6. 重新预览，检查目录及 DB 差异，确认并锁定方案。解锁、修改任意草稿内容或重新预览都会令旧确认失效。
7. 执行单目录，或者勾选多个已锁定目录顺序执行。批量复用相同单目录流程；发生失败时后续目录暂停，不是跨目录的原子事务。
8. 可选“整理后检查快捷方式”。媒体和 DB 完成后返回具体快捷方式路径、目标及冲突；核对后再点击“确认生成本目录快捷方式”。不会把“检查”作为创建授权。

切换页面保留当前草稿，切换所选根目录会清除原根目录的预览。处理结果、阶段、对象、失败原因和详细日志进入框架的处理详情面板。

## 自动分类约定

自动整理统一使用 `作品名_压制格式_分类名`，例如 `魔法少女リリカルなのは_BDRip_Disc`；下级分类目录不重复附加压制组。标准命名的整理目标提供作品名和格式，非标准手填目标则使用已确认的作品元数据。通用基类按注册的分类函数数组依次筛选，首次匹配即确定归属；默认只有下表 11 类。旧的 `Other` 统一进入 `Others`。平铺正片与字幕也进入 Disc，PV / Interview / EV 等未注册的独立文件夹整体进入 Others，不保留压制组专用例外；需要例外时由独立派生类注册后选择。压制组仍作为数据库字段保留，不再决定默认整理算法。

对于 `SP` / `SPs` 等混合发布包装目录（大小写不敏感，BDRip / DVDRip 等格式共用），分类函数处理其直属文件与资源文件夹，不再套回 SP / SPs。例如 `SPs/Menu01.mkv` → `作品_BDRip_Menu/Menu01.mkv`、`sp/NCOP01.mkv` → `作品_DVDRip_OP+ED/NCOP01.mkv`。编号预告如 `Preview01v2`、`Trailer1` 属于未注册特典，进入 Others 而非正片 Disc。CDs / Scans 本身匹配 CD / Image，整体继承类别并以新分类根替换包装层。独立文件夹一旦匹配就保持内部层级，例如 `SPs/Menu/01.mkv` → `作品_BDRip_Menu/Menu/01.mkv`、`CDs/Album/01.flac` → `作品_BDRip_CD/Album/01.flac`；未知 `Unknown/{01.mkv,cover.jpg}` 整体进入 `作品_BDRip_Others/Unknown/`，不按内部扩展名拆散。规则通过基类复用，手工目标仍优先。同名目标必须手动解决，不能覆盖。

| 分类 | 自动处理约定 |
| --- | --- |
| `OP+ED` | 文件名有明确 OP、ED、Opening、Ending 等片头片尾标记的视频 |
| `CD` | 音乐、音频资源；能与正片明确对应的外置音轨随正片进入 Disc |
| `Music` | 人工整理目录，内部完整保留，不作为新音频的自动目标 |
| `Menu` | 有明确 Menu 菜单标记的资源 |
| `CM` | 有明确 CM 广告标记的视频、字幕或目录 |
| `Others` | 所有未匹配资源的最终兜底；未知独立目录整体收纳 |
| `Disc` | 正片及其解压字幕、配套音轨；已有 `_01`、`_02` 等集数目录保留并复用 |
| `Fonts` | 字体文件及明确的字体资源 |
| `Subs` | 字幕压缩包；解压字幕应与对应正片同目录 |
| `Booklet` | 人工整理目录，内部完整保留，不作为新图片的自动目标 |
| `Image` | 图片类资源 |

Other / Others 作为未分类容器，其直属文件和文件夹在再次整理时重新经过分类数组，因此新增 CM 等规则可以接管以前落入兜底的资源；其中仍未匹配的独立子文件夹继续整体保留在 Others 内。

Music / Booklet 的人工保护优先于内部文件类型识别；分类根按规范统一命名，但内部内容不重筛、不拆分。任意层级的 `_Music` / `_Booklet` 或带作品前缀的同类标记，以及直属的 Music / Booklet 都受保护。原始专辑包 `CDs/专辑/Booklet` 中的普通附属目录跟随整个专辑，不拆开封面与音频。已有 Subs 中的解压字幕需要与实际正片唯一匹配后才建议移动；不能唯一匹配时提示手动选择。字幕或音轨匹配多个最终分集目录时仍需手动指定目标。手改文件目标会取消“已整理完成”，重新预览后才能确认。

分类实现位于 `category_rules.py`：`filter_music`、`filter_booklet`、`filter_cd`、`filter_subs`、`filter_fonts`、`filter_menu`、`filter_cm`、`filter_op_ed`、`filter_image`、`filter_disc`、`filter_others` 均可由派生类覆盖。输入是只读的 `ResourceContext`，返回 `CategoryMatch` 或 `None`；调用 `register_category("新类型", self.filter_new, before="Disc")` 注册扩展，名称自动用于目标目录，不必修改执行器或新增硬编码后缀。规则顺序决定优先级，Others 固定最后，派生兜底返回 None 也不会丢失资源。将派生整理类登记到 `STRATEGIES` 后，现有界面通过同一个列表接口提供选择。

媒体完成状态独立于 DB 是否匹配或待补齐；缺少 DB 记录不表示媒体需要重排。父作品目录只作为查找线索，子目录已明确指向剧场版、续作时，不会仅凭父目录同名就绑定到 TV 记录。

## 代码边界与复用

| 位置 | 职责 |
| --- | --- |
| `backend/directory_organizer/category_rules.py` | 无磁盘访问的分类函数注册表、默认 11 类、共享资源上下文与匹配结果 |
| `backend/directory_organizer/strategies.py` | 通用布局基类和通用整理类；目录资源归属、元数据推导、命名、分集与配套资源关联 |
| `backend/directory_organizer/snapshots.py` | 只读扫描、文件指纹、来源及目标安全路径校验 |
| `backend/directory_organizer/service.py` | 独立子目录草稿、预览、版本检查、批次协调 |
| `backend/directory_organizer/execution.py` | 同卷排他移动、逐文件执行收据、失败回滚及空目录清理 |
| `backend/directory_organizer/web.py` | HTTP 适配，接入公共任务队列与处理日志 |
| `frontend/index.js` | 可独立测试的控制器、功能注册、目录列表与编辑面板 |
| `frontend/structure-preview.js` | 只读前后目录树投影及最高层移动归并；不生成执行操作、不访问磁盘 |
| `frontend/style.css` | 本功能专属布局 |
| `tests/` | 临时目录后端测试与模拟 API / DOM 前端测试 |

DB 不是本功能的第二份数据。记录来自 `collection_detail.catalog_edit_service`；预检和保存最终复用收集列表的 `preview_save_yaml_from_ui_body` / `browse_save_yaml_from_ui_body`，包括验证、版本指纹、备份和缓存失效。整理类不得直接写 DB 或移动文件。

快捷方式通过 `collection_detail.shortcut_service.preview_shortcuts` / `apply_shortcuts` 调用原索引目录生成逻辑，使用明确的作品、压制记录范围。名称、日期格式、目标验证与冲突判断只有一个来源；生成依据是已保存的作品 DB，而不是整理草稿或索引缓存。

原生文件夹选择器位于 framework common；前端请求通过公共 `fetchJson` 进入统一处理详情。纯前端测试不会调用真实文件系统。

## 安全边界

- 扫描、查找和预览只读。修改草稿不会保存 DB、移动媒体或创建快捷方式。
- 每批最多 64 个不同计划，按提交顺序处理。计划保存在当前进程内，1 小时后失效；服务重启后需重新预览。生成新预览会取代同子目录的旧预览。
- 执行前复核来源快照、文件签名和 DB 版本；同一批次修改同一 DB 记录或写入同一文件时检查冲突，不能用后一个目录覆盖前一个目录的已确认改动。
- 当前只支持同卷移动。不支持符号链接、联接及硬链接媒体；不接受绝对目标相对路径、`..`、保留设备名等危险路径。
- 不覆盖已有文件，不自动合并重名文件。成功后只尝试删除本次实际移动文件的来源父目录及原范围内祖先中的空目录；无移动时不清理，既有无关空分类目录保留，绝不递归删除非空目录。
- 媒体移动后才提交已预检 DB 修改。DB 尚未提交时的失败尝试回滚媒体；DB 已提交后不把媒体反向回滚造成新的不一致。外部修改、进程中断或回滚失败需要根据收据核对，不能宣称所有失败都可自动恢复。
- 执行收据位于 `data/features/directory-organizer/history/<plan-id>.jsonl`，按事件追加。常规处理日志仍使用框架的日志目录和查看面板。
- 快捷方式需要自己的具体预检和第二次确认；已有冲突不自动覆盖。无关作品与压制记录不在处理范围内。
- 前端不复用失败或结果未知的旧执行计划；网络中断后需检查处理详情并重新预览，不自动重发媒体 / DB 写操作。

## HTTP 接口

均为 `/api/directory-organizer/` 下的 POST，复用框架来源检查与任务跟踪：

- `choose-directory`：系统文件夹选择，取消保留原输入。
- `scan`：扫描根目录和直属子目录。
- `catalog`：查询已有作品记录及其完整原始数据。
- `preview`：单子目录只读预览，返回不可变计划 ID、草稿、完整文件计划和来源目录快照（含空目录及结构是否完整的标记）。
- `execute`：明确确认的计划 ID 列表，顺序执行。
- `shortcuts`：指定关联记录范围的快捷方式预检或确认生成。

目录树默认展开根目录，选择与展开分离；根也可以折叠。左右两栏均根据实际高度分页，不设置内部纵向滚动；目录分页保留祖先上下文，文件不混入左侧树。展开、选中及分页状态分别保留；长名称单行省略并提供完整提示。公共浏览器位于 `framework/frontend/src/common/directory-browser.js`，公共页签组件位于同目录的 `section-tabs.js`。结构仅表示本次所选资源的前后投影，并非目标磁盘的全部已有资源。跨根移动时，原处保留的内容或空目录仍显示为来源分支。

只有某个目录的全部后代文件进入唯一目标前缀且相对位置不变、没有保留的空分支或混入其他来源内容时，才能归并为一条目录移动；有内部改名、拆分或部分保留则显示更下层目录 / 文件。结构快照不完整时不归并目录。归并仅改变展示，执行仍使用完整逐文件计划进行安全校验和移动，不直接对整个目录执行重命名。

详情窗口默认只显示移动文件，也可切换全部；逐文件显示来源、目标并支持手动编辑，每页最多 200 项。修改立即使旧确认失效，必须重新预览；切换子目录、重新预览或执行会关闭旧详情，窗口关闭或 Esc 不执行文件操作。所有文件目标仍包含于服务端预览中，不以树是否展开、摘要是否归并或详情窗口当前页决定实际操作范围。
