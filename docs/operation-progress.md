# 通用事务进度

## 使用

- 点击顶部状态提示、业务提示旁的「查看处理详情」或右下角「处理详情」，打开共用窗口。
- 左侧选择任务，右侧显示当前阶段、实际计数、耗时、当前文件 / 目录和时间线。
- 关闭窗口不取消任务，不重复执行；完成或失败后仍可查看记录。
- 未知总量仅展示步骤与计数，不推算百分比。回滚、部分失败、跳过项和连接中断分别明确显示。
- 「处理结果 / 错误明细」展示业务计数、具体失败 / 跳过项、未关联快捷方式路径及目标；不再要求返回原页面才能定位问题。
- 点击「实际处理日志文件」可查看真实 `.log` 文件路径。「打开日志文件」使用系统关联的日志查看器 / 编辑器，可用 Ctrl+F 搜索；也可下载完整文件。没有关联程序时显示具体原因，仍可使用面板内查看和搜索。
- 面板提供整个文件的普通文字搜索（不区分大小写），返回行号，点击匹配项定位原文。每批最多 50 项、扫描最多 8 MiB；未到文件末尾会明确提示「继续搜索」，不是仅搜索当前显示的片段。内嵌原文每次读取最多 64 KiB，支持从头刷新、下一段和读取新增日志；不会重新执行业务操作。
- 警告和失败展示处理动作、步骤、对象、来源 / 目标路径、数据库文件与记录标识、实际原因；异常还记录异常类型、代码文件 / 行号 / 函数和调用堆栈。未知信息留空，不猜测失败位置。
- 「历史日志 / 刷新」和「更早日志」可读取应用重启前的操作。上次未记录终态的操作会明确提示中断 / 结果待核对，不视为成功；当前仍在运行的操作会恢复进度查询。
- 内存只保存近期摘要：后端每项最多 200 条事件、128 项完成记录及 30 分钟；前端每项最多 160 条事件、60 项完成记录。活动任务不被清理。完整的白名单诊断明细写入持久日志，面板仅显示最多 80 项摘要并提示剩余数量。

## 日志文件与边界

生产桌面应用和本地服务统一写入共享工作区：

```text
data/framework/logs/operations/
  YYYY-MM-DD/
    HHmmss-微秒_操作UUID.log
    HHmmss-微秒_操作UUID.jsonl  # 内部结构化旁车，用于恢复历史状态
data/framework/logs/application/
  YYYY-MM-DD/
    desktop.log
```

目录、文件名和可读日志使用本地时间，格式为 `[YYYY-MM-DD HH:mm:ss.SSS][INFO/WARN/ERROR] 详情`；结构化事件保留带时区的 ISO 8601 时间戳。每个操作独立文件记录排队、开始、进度、结果、异常堆栈及操作 ID，多行信息的每一行都有日期与级别前缀。旧 JSONL 首次查看时按需生成同名可读 `.log`，不会改写或删除旧文件。文件长期保留，不因内存清理被删除。页面校验错误和本地完成提示单独记录，不猜测归属到并行执行的其他任务。

```text
[2026-10-03 10:20:30.123][WARN] 补建快捷方式：目标目录不存在
[2026-10-03 10:20:30.123][WARN] 阶段=核对目标；对象=示例作品；目标路径=U:\示例作品\示例作品_BDRip；原因=目标路径不可用
```

上述仅为格式示例，实际日志值来自当次处理，不会自动执行任何修复。

日志只记录操作路径（无查询参数）、白名单计数及诊断字段；不复制请求正文、上传文件、整份作品 DB 或异常局部变量。日志仍可能含本地作品路径，分享前应自行检查。磁盘不可写时业务不会因此中止，处理详情明确显示日志降级原因。

桌面启动、运行和关闭日志也按本地日期分档；跨天后下一条日志自动写入新日期目录，同日启动继续追加。原来的 `desktop.log` 和轮换备份保持不动。操作日志目录中的 `.lookup/` 是 UUID 查找索引，用于避免每次请求扫描全部历史文件，不是业务数据。

读取端点仅接受操作 UUID 和分页参数，不接受任意文件路径；拒绝目录重解析点、符号链接和多硬链接文件。操作日志与作品数据库、目录缓存相互独立。

## 扩展方式

前端共用 `window.NimdaOperationCenter`，请求经 shell 的 `fetchJson` 自动接入，不需要每个页面建立自己的轮询器。自定义前端操作可使用：

```javascript
const task = window.NimdaOperationCenter.start("处理事务");
try {
  task.progress("正在检查", { completed: 2, total: 5, unit: "项", detail: "当前对象" });
  task.finish("处理完成");
} catch (error) {
  task.fail(error);
}
```

业务提示按钮使用 `data-operation-details`；可增加 `data-operation-prefix="/api/collection-detail"` 打开该模块最近的任务。API 中文名称和通用页面布局集中在 `operation-center.js`，样式位于 `operation-center.css`。

后端服务只需上报实际阶段：

```python
from work_catalog_yaml.operation_progress import operation_context, report_progress

with operation_context(action="读取收集记录", stage="解析 YAML", yaml_source_rel="当前文件.yaml"):
    report_progress("读取数据", completed=3, total=12, unit="文件")
```

无 HTTP 操作上下文时为空操作，CLI 不依赖 Starlette。高频循环需节流，不要逐文件刷日志；不可细分的外部调用报告开始 / 返回。

## 请求与生命周期

- 客户端使用随机 UUID `X-Nimda-Operation-Id`；重复 ID 拒绝，不合并或重复执行事务。
- API 适配层注册排队状态，工作线程内部记录开始 / 结束，并通过 ContextVar 隔离并发事件。
- `GET /api/operations/{operation_id}` 读取线程安全快照；内存已淘汰时回查持久日志，返回 `no-store`。
- `GET /api/operations?limit=30&before=...` 按时间分页读取历史；`GET /api/operations/{operation_id}/log?offset=0&limit=65536` 按字节分页读取原始日志。
- `GET /api/operations/{operation_id}/log/search?q=...&offset=0&limit=50` 全文分批搜索，返回行号、字节定位和是否到文件末尾；`GET .../log/file?download=1` 下载完整可读日志。
- `POST /api/operations/{operation_id}/log/open` 按操作 UUID 安全定位 `.log` 后请求系统打开，不接受用户传入任意文件路径。所有日志查询和打开接口均受同源检查保护。
- `POST /api/operations/client-events` 持久化页面校验 / 本地完成结果，采用独立 UUID，不能覆盖服务端操作。
- API 中时间为 UTC ISO 8601，界面和可读日志转换为本地时间。状态：`queued/running/succeeded/warning/failed/cancelled`。
- 客户端只串行轮询进度，不自动重试业务请求。断线不等于服务端停止，显示「结果待确认」并继续尝试核对。
- HTTP 200 中明确的部分失败 / 跳过同样为 `warning`，断线后只读取进度也不会误报全部成功。
- 未捕获的页面运行异常、异步异常及功能加载失败也记录到通用处理详情和客户端日志。
- 终态快照短暂读取失败会有限退避重试；不会因此重试保存、移动或快捷方式生成等业务请求。
