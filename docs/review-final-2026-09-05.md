# 2026-09-05 工程、复用与显示细节复审

本轮在前两轮模块拆分和性能优化之上继续修改，保留原有全部未提交改动。没有修改真实数据库、配置或媒体，没有创建快捷方式，没有提交 Git/SVN 或重新打包桌面应用。

## 已修复的问题

| 问题 | 调整 | 验证 |
| --- | --- | --- |
| 同一数据库行命中缓存后，后续引用可能绕过作品名和内容哈希验证 | 每个 `catalog_ref` 逐次校验；引用哈希绑定解析时的同一份字节 | 正确引用后接错误名称/哈希均被拒绝；新阶段发现磁盘变更 |
| 资源库搜索结果被强制展开，点击后无法折叠 | 搜索和普通浏览使用独立折叠状态；清空搜索恢复普通状态 | 单项、全部折叠与清空搜索回归 |
| 同一目标目录只显示前 200 个文件，剩余明细无法检查 | 每个目标目录独立分页，每页最多 200 个文件；折叠后保留页码 | 450 文件的三页、边界、转义、焦点和计划不变性回归；真实浏览器实测 |
| 旧快捷方式异步请求可能覆盖当前悬停项的提示 | 核对当前悬停对象；使用最新鼠标位置；离开索引后保持隐藏 | 两个请求逆序返回、鼠标移动、离开索引回归 |

分页只影响显示。执行计划仍包含全部文件；预览失效规则、执行确认、数据库写前哈希检查及回滚边界没有放宽。

## 抽象与复用

- 新增 `landing_catalog.CatalogReadSession`：在一个只读阶段内共享文件内容、解析结果及按需构建的压制记录。候选筛选先看基础信息，只对匹配项构建完整记录。生命周期不跨请求、数据库写入或预览到执行的边界。
- 快捷方式预览、修复候选、共享目标绑定和来源作品绑定复用该会话，减少同一阶段的重复读取。
- 新增 `scripts/lib/workspace.ps1`，统一源码启动、桌面源码启动、整理 CLI、测试和基准的后端发现及环境设置。显式绑定源码工程根，避免继承打包版环境后读取错误的配置/数据目录。
- 环境变量和工作目录在成功、异常及嵌套调用后恢复；原生子进程退出码保留。验证了 Windows PowerShell 5.1 和 PowerShell 7。
- 新增 `scripts/benchmark.cmd` / `.ps1` 统一性能复测入口，不再要求手工拼接多个后端的 `PYTHONPATH`。

## 性能结果与限制

300 条数据库记录、5 条相关作品、3 种候选查询的合成场景：完整记录构建从 **900 次降至 5 次**，文件内容读取从 **3 次降至 1 次**。这是重复工作的减少，不代表整个应用快了 180 倍；首次 YAML 解析仍有成本。

统一基准从工程外目录 `E:\Project` 成功运行。本机本轮复测：

| 场景 | 结果 |
| --- | ---: |
| 配置 API 热缓存中位数 | 52.436 ms |
| 作品列表热缓存中位数 | 113.910 ms |
| 整理器数据库加载热缓存中位数 | 76.308 ms |
| 合成资源树展开中位数 | 2.997 ms |
| 合成作品匹配中位数 | 2.035 ms |
| 13,020 目录、顶层折叠重复 HTML 生成 | 0.15 ms / 16,410 字节 |
| 10,000 文件、明细关闭重复 HTML 生成 | 0.20 ms / 35,852 字节 |

首次配置请求为 1,717.254 ms；热缓存数值不能用于描述冷启动。前端基准仅测字符串生成，不包含浏览器布局和绘制。时间存在运行波动；重点回归记录数量、读取次数及输出稳定性。各 API 场景三轮输出哈希一致。
