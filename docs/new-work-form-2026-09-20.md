# 新增作品表单（2026-09-20）

收集列表的「新增行」改为「新增作品」独立弹窗，不再直接插入空白行。

## 操作流程

1. 点击「新增作品」，无需先打开编辑模式。
2. 填写作品名、品类、国家 / 地区、播出类型及可选日期。
3. 收集信息可选填：作品根目录、多个压制版本（格式 / 组 / 目录）、标记。
4. 点击「加入待保存列表」，列表进入编辑模式，新增记录显示「待保存」。
5. 检查后点击「保存到 YAML」才写入数据库。

弹窗显示按国家及开播年份推导的写入位置（2026-09-21 修正）；年份未知时回退当前年份，修改国家或日期后提示随之更新。日期显示为 `YYYY-MM-DD`，传入保存流程时转换为 `YYYYMMDD`；允许空日期和 `00` / `X` 未知位。后端独立推导落库文件并负责最终校验，不信任客户端传入的新记录文件名。复制路径外围的引号和方向控制符会清理，内部空格及合法 Unicode 保留。

## 交互与数据保护

- 空作品名不能加入；空压制行不保存，填写了压制信息的行必须指定格式。
- 已填写内容点击取消或按 Esc 时先提示确认放弃，支持继续填写；未填写直接取消，不产生记录。
- 保存 / 加载期间禁用新增和冲突操作，保存请求不能重复提交。
- 弹窗打开后如果列表数据已切换，旧表单不会提交到新列表。
- 新记录即使没有对应的已渲染表格行，保存时仍从草稿中收集，不会遗漏。
- 保存成功但刷新失败时，旧列表变为不可重复保存，明确提示重新加载数据库，避免重复新增。
- 独立组件 `new-work-dialog.js` 管理表单和草稿，列表整合仍由现有 shell 管理；弹窗本身不请求 API、不写文件。

## 未保存新增行置顶（2026-09-28）

- 未保存的新增记录固定在列表顶部，最新添加的在最前；切换排序列、升降序或修改名称、日期不改变草稿之间的先后。
- 新增顺序跨国家、年份和分类统一计算，不依赖数据库行号。该顺序只存在前端，不写入作品数据。
- 草稿不被列筛选隐藏，列表上方明确提示置顶数量；已有记录继续正常筛选。
- 保存失败仍保留置顶；保存确认成功后取消置顶，即使后续刷新失败也不会把已保存记录继续当成未保存草稿。
- 保存并刷新后保留当前排序与筛选，同时清空旧行号对应的删除状态和枚举草稿，避免重复操作。
- 前端资源版本更新为 `v135`，本轮不修改实际数据库或媒体。
