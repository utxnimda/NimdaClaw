# 收集列表：作品信息

点击收集列表中的作品名，打开只读详情窗口。默认使用「可视化」模式，也可以切换到「JSON」查看完整记录的层级结构。编辑模式仍可使用名称旁的「编辑」修改作品名。

作品名不显示下划线，仍保留悬停颜色与键盘焦点提示。JSON 模式提供「全部展开 / 全部折叠」：展开覆盖所有层级及分页，分批渲染并显示进度；折叠会停止未完成的展开并释放节点。切换视图、关闭或打开另一个作品也会停止后台展开。

## 数据来源

- 已保存作品：点击时按需读取对应 YAML 中的完整单条记录，包括标准属性之外的字段，而不是列表摘要。列表尚未保存的修改不会被误当成数据库已保存内容。
- 上传文件：展示当前上传内容的原始单条记录，不读取服务器上同名文件。
- 新增草稿：展示当前草稿生成的作品结构，并明确标记尚未保存。
- 保存成功但刷新失败：要求先重新载入列表，避免将临时行号当成数据库记录编号。

可视化模式中的日期使用 `YYYY-MM-DD`，空组使用 `—`；JSON 保留原始日期和组值。所有查看与模式切换均不修改数据库、媒体文件或快捷方式。

## 实现边界

- 独立组件：`apps/features/collection-detail/frontend/work-detail-dialog.js` 及专用 CSS。组件通过 `loadRecord` 获取数据，不自行写文件。
- 只读接口：`POST /api/collection-detail/work/detail`，传入 `yaml_source_rel`、`index_in_file`、`source_sha256`。
- 数据库列表仅增加来源文件摘要，完整记录在点击时读取，避免每次加载列表都传输全部原始数据。
- 来源仅允许当前配置中的数据库文件。文件已变更时返回 409，要求重新加载列表，避免旧行号指向另一个作品。
- YAML 日期 / 时间标量转为可读 ISO 字符串；无法无损表示为 JSON 的类型明确报错，不静默丢字段。
- 展示内容按文本渲染；JSON 分支按需展开，避免一次创建大量节点。
