# 2026-09-05 性能优化

本轮先测量数据库加载、目录匹配、资源树展开和前端文件树，再优化重复工作。保留已有未提交修改；没有操作真实媒体、数据库或快捷方式，没有重新扫描真实资源库，也没有提交或重新打包。

## 实测结果

本机同一 Python/Node 环境。API 基准读取原有 72 个 YAML 文件，共 706,635 字节；每个场景连续执行 3 次，报告中位数。优化后列表和目录整理数据库加载复用了配置请求已解析的内容，因此下表是进程内热缓存指标，不是冷启动指标。

| 场景 | 改前 | 改后 | 说明 |
| --- | ---: | ---: | --- |
| 配置 API | 1,659.966 ms | 50.848 ms | 包括枚举/组注册表与数据库目录信息 |
| 完整作品列表 | 1,586.849 ms | 94.110 ms | 输出 1,039,440 字节；前后内容 SHA-256 相同 |
| 整理器数据库加载 | 1,557.436 ms | 67.484 ms | 加载全部品类；前后记录表示的 SHA-256 相同 |
| 资源库目录展开 | 约 52.20 ms | 3.048 ms | 临时夹具：40 作品、80 压制目录、320 文件 |
| 作品名匹配阶段 | 258.8 ms | 2.044 ms | 合成 300 作品、100 项别名，4 次目录查询与 1 次方括号查询 |

首次配置请求仍需解析内容：本轮测得 1,685.908 ms，与改前同一量级。解析缓存不落盘，重启后重新建立；不能将热缓存倍数理解为整个应用或冷启动的加速倍数。

前端使用 Node 测量纯 HTML 字符串生成，**不包含浏览器布局、绘制或网络耗时**：

| 场景 | 重复渲染改前 | 重复渲染改后 | HTML 体积改前 → 改后 |
| --- | ---: | ---: | ---: |
| 13,020 目录，顶层折叠 | 72.87 ms | 0.15 ms | 9,413,910 → 16,410 字节 |
| 40 路由、10,000 文件，明细关闭 | 183.02 ms | 0.20 ms | 1,932,641 → 35,852 字节 |

整理文件明细仍需在首次渲染时建立路由索引，本轮首次耗时 16.70 ms；其后复用同一预览的数据。

## 优化内容与正确性边界

### YAML 与列表加载

- 性能分析显示，原列表加载约 94% 的累计耗时在 YAML 解析。同一批文件在配置、列表、整理器入口被反复解析。
- 新增 `yaml_cache.YamlParseCache`，文件与字符串入口复用按完整内容建立的解析结果。每次读取文件仍读取当前内容，不使用路径、大小或修改时间替代内容检查。
- 返回值使用深复制；修改返回的作品/配置对象不会污染下一次加载。异常不缓存，文件删除、同尺寸且保持修改时间的修改、原子替换均仍能被读取入口发现。
- 缓存有 128 条和估算 32 MiB 的双重淘汰界限，超大文档不缓存。本机基准保留 75 条，估算 6.78 MiB；这不是进程峰值内存上限，不包含瞬时解析/复制与容器附加开销。
- 作品加载只做一次收集字段规范化，去掉两次冗余深复制/重复规范化；输入对象隔离、路径校验和最终输出保持不变。

### 目录匹配

- `CatalogMatchIndex` 在每次预览内预处理作品名、别名和压制值；完整名称直接查表，同格式文件复用候选索引。
- 合成场景的身份规范化调用从 422,805 次降到 1,609 次。
- 不跨请求缓存作品匹配；新预览读取新配置与记录，重复数据库记录不会被合并或丢失歧义。

### 资源库

- 删除目录展开时被 `setdefault` 默认表达式提前执行的重复空缓存/配置构建。
- 使用 `os.scandir` 复用单次目录枚举返回的元数据，并合并计数遍历。临时夹具的 `Path.stat` 调用从 1,562 次降至 241 次，目录枚举仍为 121 次。这里统计的是 Python 方法调用，不直接等同于操作系统调用次数。
- 不缓存跨扫描的媒体状态；符号链接、目录联接、排除路径检查与缓存原子发布/失效规则继续保留。
- 完整扫描含 YAML 写入的微型夹具约 0.367 → 0.345 秒，收益小于重复展开；不据此承诺真实大盘扫描速度。

### 前端

- 资源树折叠分支不再生成隐藏后代。
- 整理文件明细按展开层级生成，关闭时释放隐藏 DOM；父子展开状态仍保留。
- 同一预览对象复用路由索引和目录树。新预览独立建立缓存，旧预览排队的展开事件不修改新界面。
- 预览失效、人工选择、移动确认和服务端串行写入/安全关闭语义未放宽。
